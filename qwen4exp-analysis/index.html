建模方法与校准来源

纯 Prefill

950PR W8A8 · TP8 / EP8 · MTP 关闭。2026-11-13 冷请求 128K → 1、C1，三种布局各 8 个正式样本。B48、B2、B4 平均 TTFT 分别为 20.2415、25.1624、26.4207 秒。

按每 DP 一批的未命中 token 总量做线性估算。每批耗时下限取 128K 锚点折算的一个 chunk（1,536 tokens），短输入及热前缀仍需另测。缓存命中仍占池空间，QPS = DP 副本 × Batch ÷ TTFT。缓存按每请求对齐到 768 tokens，另计 9 个状态和索引 ID，再加 1 个池级 null ID。

纯 Decode

48 层 128K 热前缀 → 96。950DT TP4 / EP4 MTP5 使用 B1、2、4、8、16。A3 TP8 / EP8 MTP5 与 950DT MTP 关闭使用 B1、4、8。线上耗时与独立 trace 核对 Batch 后配对。950DT 提交 B32 的 trace 主要运行在 B17，该档从校准中排除。

Batch 档间线性插值 ITL 和 TPOT。外推到最大测点之后时，沿用末个测点的时延。默认上下文占比为 0%，沿用 128K 的时延。可用比例 f 按 (1 − f) + f × 平均上下文 / 参考上下文 调整时延。平均上下文包含首 token 后生成区间的中点。

手动填写每轮产出时，TPOT = ITL ÷ 平均产出。MTP 关闭时沿用实测 ITL 和 TPOT。D QPS = DP 副本 × Batch ÷ [(输出长度 − 1) × TPOT]。QPS 是稳态模型估计。

KV 容量按请求末尾的上下文估算，重复存储部分扣除已共享的对齐前缀。950DT MTP5 参考同拓扑验证日志的 624,286 tokens / rank，按 1,536 tokens 对齐。A3 和 MTP 关闭工况可填写实际容量。

流水线标注口径

点旁标出 PMU 活跃度最高的流水线，点击 Batch 可看 MTE1、MTE2、MTE3、Vector、Cube、Scalar 和 Fixpipe 的读数。

活跃度 = profiler 流水线耗时字段之和 ÷ 有计数的 kernel 设备耗时之和。Scalar、MTE2、MTE3 在单次调用内取 AIC/AIV 较大值。各流水线可以重叠，百分比之和可能超过 100%。

达到最高项 90% 的流水线并列，超过两项显示 Mixed。PMU 覆盖低于设备耗时的 80% 时，标为通信或计数不足。标签用于定位值得检查的流水线，确认瓶颈还需结合等待时间与优化前后验证。Ascend 计数说明 ↗
