# 参考模板与适用模式

仅在已明确要求 HTML 讲解后，按任务选择以下结构。借鉴解释方法和交互，不将模板的技术结论直接套用到当前源码。

## 调度、调用链与异步传输

来源：[bowgneo / vLLM KV Connector 调度流程](https://bowgneo.github.io/posts/vllm-kv-connector-scheduling-flow/)。阅读于 2026-11-17；原文基于 v0.30.0，与本仓库已有主题的源码版本不同。

- 用系列入口拆分 Scheduler、Runner、P/D 交接和池化复用；章节名关联真实函数入口，让读者知道下一步读哪里。
- 用一条具体请求串联前缀查询、块分配、metadata 下发和完成通知；展示字段在生产者与消费者间的变化。
- 在图中标出对象所属进程、模型线程、传输线程和设备流。箭头说明派发、等待或通知，避免把 Python 返回画成设备完成。
- 解释同步点的理由：谁等哪个事件、等待保护什么数据、何时才允许块被复用；附对应源码入口。

适合：请求生命周期、Connector、异步 IO、资源所有权。可组织为“入口概览 → 阶段章节 / 泳道 → 点击步骤看输入、状态变化、源码 → 完成与回收”。

## 算子、tensor 与容量分析

来源：[biuapha / GLM-5.3-Flash 算子与 KV 分析](https://biuapha.github.io/LLM-Analysis/glm53_prefill_decode_operator_block_diagram.html?v=dede271#prompt-links)。阅读于 2026-11-17。

- 按读者问题分页面：执行总览、tensor 依赖、KV 分组、容量和性能。总览模块可进入细节，Prefill / Decode 的选择关联对应视图。
- 用颜色与线型表达 activation、cache、indices 和 metadata；选中节点或连线后显示输入、输出 / 消费者、shape、公式和源码。
- 缓存图标注逻辑形状、实际字节、padding 与共享关系；区分视图、原地更新和物理分配，防止重复计算。
- 计算器标明单位、配置、数据来源及假设；实测、校准、外推和理论上限分别标识，不由图形推导未经验证的性能结论。
- 保留可审计来源和更新记录；可公开的会话链接只在用户提供或授权公开时登记，不推导或发布私人会话。

适合：算子数据流、KV 布局、参数影响。先做最小可用的总览与详情，只有参数化分析确有帮助时再加入计算器或导出。
